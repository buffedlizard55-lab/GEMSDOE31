# GEMSDOE31 · H31 candidate register and preregistration — 2026-10-04

**Status:** the H31-A experiment design was frozen before any H31 feature construction/model fit. A 2026-10-04 source-access addendum updates H31-B feasibility before the first H31 fit; it does not alter the H31-A features, folds, model, metric, draws, variogram or promotion gate. No H31 model has been fit. This is a prospective design, not a result. Expected gains below are planning ranges for a catalogue-gap proxy only; they are not measured effects, confidence intervals, or leaderboard-score forecasts.

## Decision target and evidence classes

- **OFFICIAL** — read from a government, competition-administrator, publisher, or official data-release page linked below.
- **OWNER-MIRROR** — bytes or claims published by the project owner in a sibling GEMSDOE repository/site; hash matches establish byte identity to that mirror, not authenticity to DrivenData.
- **COMPUTED** — reproduced from local code/data, with hashes and measurements recorded.
- **INFERENCE** — geological or modelling rationale to be tested, not a finding about the private test labels.

The scoring target is mapped fault pixels, not geothermal vents or geothermal favorability. The official challenge description says its initial private truth comprises expert-identified faults not in the public USGS dataset; the metric and staff clarifications also make clear that near-catalogue predictions can still be penalized and that some new truth may represent corrections near known traces. Consequently, catalogue proximity is a useful comparator, not evidence that a candidate is a real fault.

## H31-A frozen validation plan

### Question and comparator

Does the predeclared multiscale magnetic local-wavelength feature improve the exact GEMS distance-weighted Tversky index over the **same-fold, same-draw base model** using only the existing competition features? The local base model is a screening comparator, not a reproduction of the historically best H19-5 system. Therefore a positive H31-A result alone **cannot** authorize a weekly submission; the exact incumbent must later be reproduced on the same data-derived folds and beaten as well.

### Spatial split and labels

- Use the owner-mirror sample template to define the footprint; do not derive it from a predictor band. Use the known-fault raster as the only positive proxy labels.
- Build 8-connected components of known faults. For each of four contiguous spatial quadrants, hide whole components for a fixed 20% catalogue-pixel hide fraction; component selection is seeded and frozen before model fitting. Keep visible catalogue pixels available to the base model, and mask them from all scoring terms as stated in the staff clarification.
- Erode each scoring quadrant by 12 pixels (1.2 km) so a fold boundary does not truncate the 300 m metric neighborhood or create artificial credit/penalties. Training excludes all known-fault components touching the test block’s buffer collar.
- This is a **catalogue-gap hide-and-recover proxy**, not the undisclosed private truth. It is necessary screening evidence, not competition-score evidence.

### Frozen H31-A algorithm, seeds and reference implementation (pre-fit amendment, 2026-10-04)

This amendment fixes the previously described “predeclared scales” and draw schedule before any H31 feature construction or model fit.

- **Inputs and exact feature names:** read `tmi_hg` and `tmi_vg` as their hash-pinned 19-band values; do not use the confusing `tc` band description. Define analytic-signal amplitude `A = hypot(tmi_hg, tmi_vg)` on cells where both are finite. For filtering only, fill invalid cells with the nearest finite value, then re-mask invalid cells in the two outputs.
- **Scales and local length:** for `sigma ∈ {1, 3}` grid pixels (100 m and 300 m), let `A_sigma = gaussian_filter(A, sigma)`, `G_sigma = hypot(gradient_y(A_sigma), gradient_x(A_sigma))`, `epsilon_sigma = 0.01 × median(G_sigma)` over finite competition-footprint cells with `G_sigma > 0`, and `L_sigma = clip(A_sigma/(G_sigma + epsilon_sigma), 0.5, 30.0)` pixels. The length is a local wavelength index only; it is not an inverted source depth.
- **Two model columns:** `H31_mag_local_length = log1p((L_1 + L_3)/2)` and `H31_mag_scale_edge = sqrt(E_1 × E_3)`, where `E_sigma` is `hypot(gradient_y(L_sigma), gradient_x(L_sigma))` divided by that scale’s 99th percentile over finite footprint cells and clipped to `[0,1]`. The percentile and epsilon use unlabeled raster values only; no labels or hidden truth enter feature creation.
- **Pilot and evaluation seeds:** pilot draw `10` (all four spatial folds), final screen draws `11,12`, and fresh confirmation draws `13,14`. Per-fold component hiding and negative sampling use the fixed sibling implementation’s deterministic seed formulas. Confirmation is prohibited unless the final-buffer screen passes.
- **Reference model/control:** reproduce the current H19-5 parent as base feature families `BDE` plus registered add-ons `X1_K`, `X1_ThK`, `X1_UK`, `X2_compat`, `X2_compat_coh`, `X3_gm`, `X3_gd`; compare against the same columns with H31-A’s two columns added. Do not include H27/H30 features in either arm. Use the pinned sibling HGB parameters (`100` iterations, learning rate `0.12`, 31 leaves, 50 minimum samples/leaf, `L2=1`, class weights `{0:1,1:5}`, no early stopping), same 300,000-negative cap, ridge NMS (`sigma=1`), top `K=round(0.035 × eroded-domain pixels)`, and score-ordered 2.4-pixel Poisson thinning. Emit binary predictions for the exact DTI.
- **Pinned reference implementation and caches:** the comparator implementation is the public owner sibling [GEMSDOE25 commit `c185edd8b09e19846cf34c16050e6cf891ecc2d0`](https://github.com/buffedlizard55-lab/GEMSDOE25/tree/c185edd8b09e19846cf34c16050e6cf891ecc2d0), specifically its `src/gems25/experiment.py`, `features.py`, `families.py`, `holdout.py`, `metric.py`, `thinning.py`, and `scripts/` build path. The recreated `static_ABCD.npy`, add-ons, footprint and labels must match that commit’s `evidence/work_cache_hashes.json` exactly; record actual hashes and the sibling commit in every run. This avoids silently comparing to an unpinned implementation. This source pin is owner-controlled code, not an official organizer artifact.

### Data-derived buffer (no assumed 4–5-pixel final buffer)

1. Run a pilot out-of-fold fit with a **5-pixel / 500 m pilot collar only to obtain residuals**. The pilot distance is not the final validation setting and is not reported as a measured dependence range.
2. For held-out known-fault pixels only, compute out-of-fold probability residuals `e = y − p`. Fit the classical Matheron semivariogram `mean(0.5 × (e_i−e_j)^2)` with Euclidean UTM distances, 500 m bins from 0 to 50 km, at least 20 pairs per reported bin, and pairs only within the same 8-connected fault component **and** fold/draw. Require at least four residual cells per component group, 30 trace groups with pairs, eight populated bins, and at least 2 km of populated lag support. Fit the bounded exponential model `nugget + partial_sill × (1 − exp(−h/a))`; report its nugget, partial sill, total sill, scale `a`, 95%-sill practical range `−a ln(0.05)`, effective range in metres and 100 m pixels, pair counts, weighted RMSE/R², plateau diagnostic, and fit status. Component-bootstrap 200 replicates (seed 20261004), taking a 2.5–97.5% interval; at least 80% of bootstrap fits must be stable. A fit is unstable if the 95% range approaches 90% of the 50 km maximum lag, populated lag support fails to reach 95% of the fitted partial sill, partial sill is negligible, weighted R² is negative/nonfinite, or the range is below the first lag-bin center. Do not estimate the range from in-sample residuals or from a binary submitted raster.
3. Fit both the base and H31-A residual variograms. Set the final buffer to `ceil(max(upper 95% range_base, upper 95% range_H31-A, 300 m) / 100 m) × 100 m`. The 300 m floor is the metric support, not an autocorrelation estimate. If a variogram has no identifiable sill/range, too few same-trace pairs, or an unstable fit, the buffer is **unknown** and the holdout gate fails closed.
4. Re-run all four folds with that final buffer. Refit the variograms on the final screen’s out-of-fold residuals; if either fitted upper range exceeds the applied buffer, increase the buffer and rerun the screen on the same registered draws. Stop after three buffer iterations and fail closed if the range does not stabilize. On fresh confirmation draws, report both arm variograms; if either upper range exceeds the frozen final buffer, confirmation fails closed and a new preregistration is required rather than tuning confirmation. No weekly submission slot is touched during this process.

### Model, emitter, endpoint and promotion gate

- Fit the same frozen HistGradientBoosting presence-vs-pseudoabsence learner in each fold for base and base+H31-A; use common random numbers and the same training samples, holdout components, feature sanitation, and emitter. Feature scaling/sampling rules and random seeds are serialized before the first fit.
- Use the exact distance-weighted Tversky equations from the official page (`alpha=0.2`, `beta=0.8`, triangular support `R=300 m`) and the staff clarification that known pixels are excluded. Report each fold, pooled sufficient statistics, and the pooled index; do not average pixel accuracy or per-fold AUC as if it were the official metric.
- Screen gate: paired mean ΔDTI > +0.001, candidate better in at least 3/4 spatial blocks, no block worse than −0.010, and catalogue-hug diagnostic increase ≤0.10. Report AUC/coverage only as diagnostics. A screen pass would require fresh seeded component hides before any packaging; no tuning on the confirmation set.
- **Additional incumbent gate:** no candidate is weekly-slot-eligible unless it beats the reproduced H19-5 / current-best holdout comparator on the same data-derived buffer and passes the frozen confirmation gate. The existing cross-session score claims are not a substitute for this comparison.
