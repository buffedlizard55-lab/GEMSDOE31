Troubleshooting

“Predicted values must be in range [0, 1]”

Two measurable mechanisms in the competition's own rasters produce exactly this message.

It is not a rescaling problem The training stack carries a float32 sentinel (about -3.4e38) inside the scoring footprint, and a footprint mask taken from a feature band instead of the template strands scored pixels as NaN (SECONDHAND, GEMSDOE32 root-cause note; see knowledge/2026-10-25_lane_hypotheses.md).

What the repository does about it

The footprint comes only from the template. src/gemsdoe31/submission.py and gate G1/G2 hard-fail any non-finite cell inside it, any value outside [0,1], and (all-finite) any non-finite cell anywhere. tests/test_submission.py and tests/test_gate.py keep regression tests.

If a gate-passing file is still refused

  1. Confirm you selected the single-band GeoTIFF, not a feature stack.
  2. Try the other convention.
  3. Stop and send the gate receipt JSON to the organizers instead of re-saving modified bytes.
